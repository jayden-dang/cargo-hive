# ADR-0001: Read Cargo's internal fingerprint files as the source of truth for units and edges

Hive must know which compilation units exist and how they depend on each other, without a rustc wrapper (A1) and without invoking or replaying cargo for liveness (D3). The stable alternatives are nightly-only (`--unit-graph`, `-Zbinary-dep-depinfo`), so hive reads Cargo's unstable `.fingerprint/` JSON and hash files directly (24,855 of 24,855 edges resolved on klynt, SPIKES.md §9). Because that format is internal and already differs on nightly (`build/<pkg>/<hash>/fingerprint/`), hive accepts only an exact format signature and treats every other shape as unsupported (no deletion, no seeding), never as partially parsed (CORE-4.14, design Decision 6). Hive also reads `output-*`, a Cargo-internal file of rustc JSON diagnostics whose format the rustc book does not promise to keep stable, gated per toolchain by check (g), with a field dropped on any line it cannot parse.
